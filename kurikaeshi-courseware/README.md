# 反復強調の「に」 ・ Vます形＋に＋同動詞

一本专讲「**同一个动词说两遍**」的课件：`待ちに待った`・`考えに考えた`・`泣きに泣いた`・
`痩せに痩せた`——中间的 `に` 不是时间、也不是目的地，而是**同じ語を重ねる軸**（把相同的语
贴在一起的轴）。它把「何度も何度も（一遍又一遍）」才说得出的**反復**与**极まり（彻底）**
一次压缩进来，只用一个助词＋动词重复就演完，情绪密度极高。

课本一般不当正式条目教它——所以戏称**传说中的 N0**（超纲却日常到不行，口语、新闻、小说、
番剧里满地跑）。遇到新搭配随手丢进 `kurikaeshi.json`，重跑一次 `build.py`——卡片、振假名、
发音、题库自动重新长出来。成品是单文件 `index.html`（内嵌全部发音＋Nadeshiko 原声，离线可用）。

## 打开

浏览器直接打开 `index.html`，或起本地服务：

```bash
python3 -m http.server 8642   # 然后访问 http://localhost:8642/kurikaeshi-courseware/
```

## 构造与规则

**公式**：`Vます形（連用形） ＋ に ＋ 同じ動詞（自由活用）`

| 前半（固定） | に | 后半（自由） |
|---|---|---|
| 待ち（待つ） | に | 待った／待って／待っている／待つ |
| 考え（考える） | に | 考えた／考えて／考えます |
| 泣き（泣く） | に | 泣いた／泣いて |

- **允许**：重ねるだけ積み上がる动词——変化（痩せる・増える）・感情（泣く・笑う・悩む）・
  可反复的动作（飲む・探す・調べる）。
- **禁区**：一度きり・移動・無意図的动作——`行きに行った✗`・`死にに死んだ✗`・
  `生まれに生まれた✗`（重ねても積み上がらない）。
- **言い換え**：`泣きに泣いた ≒ 何度も何度も泣いた`；副词只数回数，〈に〉型把动作本身演成
  加速重演，并额外带上「彻底／尽くした」的完成感。

## 五大分類（20 型）

| 组 | 内容 | 代表 |
|---|---|---|
| 🔔 待望・探索 | 盼/找 的动作重复本身就是努力 | 待ちに待った・探しに探した |
| 🧠 思案・煩悩 | 头脑里的反刍 | 考えに考えた・悩みに悩んだ・調べに調べた |
| 😭 感情の噴出 | 情绪一次放光 | 泣きに泣いた・笑いに笑った・謝りに謝った |
| 🌊 変化・程度の極み | 程度层层加深 | 痩せに痩せた・揺れに揺れた・売れに売れた・負けに負けた・酔いに酔った・濡れに濡れた・磨きに磨いた・重ねに重ねた・数えに数えた |
| 📏 使い方の規則 | 公式・禁区・言い換え | 待ちに待つ（公式）・行きに行った（禁区）・何度も何度も（言い換え） |

## 增长闭环：发现搭配 → 入册 → 重建

### ① 找素材：nadeshiko / moji 双源

```bash
nadeshiko search "待ちに待った" --once -n 5   # 真实番剧/日剧台词（必带 --once）
moji 考えに考えた --once                       # 教科书例句（抄 jp/cn）
```

- 真实台词按结构 `{ "jp","en","cn","media","ep","at","url","audio","thumb" }`
  放进条目的 `nadeshiko[]` 数组，build 自动下载原声并渲染场景卡（缩略图＋▶）。
  注意 Nadeshiko 的模糊搜索会命中近似句，**只挑真正含该型的台词**；
- jp 里的汉字一律用「」，别写裸 ASCII 双引号；Nadeshiko 自带行内注音时由 build 转 `<ruby>`；
- 自写例句（`examples[]`，每条约 3 句，`jp` + 中文 `cn`）由 TTS 负责发音。

### ② 入册：往 kurikaeshi.json 里加一条

```jsonc
{
  "id": "machi",
  "word": "待ちに待った",
  "read": "まちにまった",
  "tag": "待望",                       // 型・用法徽标
  "pattern": "待ち（待つの連用形）＋に＋待った",
  "group": "machi", "level": "N1", "emoji": "🔔",
  "meaning": "盼了又盼、等了又等——把「等」这个动作重复到极限……",
  "examples": [
    { "jp": "待ちに待った週末がやってきた。", "cn": "期盼已久的周末终于来了。", "src": "moji" }
  ],
  "nadeshiko": [ /* 可选，见上 */ ],
  "note": "金色小贴士（语感/规范提醒）",
  "quizzes": [ { "type": "judge", "q": "……", "ans": true, "exp": "……" } ]
}
```

### ③ 重建：一条命令自动生长

```bash
python3 build.py           # 新音自动合成；働き認識／運用填空／聴解判別各 +1 問
```

## 条目字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✔ | 全局唯一，定了别改（错题本靠它记忆） |
| `word` | ✔ | 展示的型（如 待ちに待った）；`word[:-1]` 会被用作運用填空的挖空核心 |
| `read` | ✔ | 假名读音，也是单独朗读的文本 |
| `tag` |  | 型・用法徽标（待望／思案／禁区／公式…） |
| `pattern` |  | 该条的构造拆解（详情里显示「🧩 型」） |
| `group` | ✔ | 分组 id（顶部 `groups` 定义名称与配色） |
| `level` | ✔ | JLPT 档位标签（本型多为 N1–N2，戏称 N0） |
| `meaning` | ✔ | 中文解释（「働き認識」题的答案来源） |
| `examples` | ✔≥1 | 例句 3 条上下（`jp` + 中文 `cn`），每条自动合成发音并加 pykakasi 振假名 |
| `nadeshiko` |  | 原声台词数组 → 「🎬 原声台词」场景卡（自动振假名） |
| `note` |  | 金色小贴士（💡 教学提示/规范提醒） |
| `quizzes` |  | 自作题：`choice` / `judge` / `listen`（choice 的 `ans` 是下标，judge 是布尔） |

> 例句展示层由 build 自动加 **pykakasi 振假名**（只作用于 display 副本，TTS/出题/填空用素文），
> 页面里 `<ruby>` 即浏览器原生注音。pykakasi 的错读（重ね→おもね、末→まつ 等）在
> build.py 顶部的 `_READING_OVERRIDES` 里整句矫正，或直接把例句改得更好读。

## 内容页签

🗺️ **一覧**（5 大分類总览）→ 📖 **詳細**（型卡＋働き＋🧩 型＋例句原声＋🎬 原声台词场景卡）→ 🎯 **クイズ**

题库 4 层：📘 働き認識（全部 20 型）・✍️ 運用填空（把重复的动词找回来）・🎧 聴解判別（听句选型）・
⭐ 自作題（公式/禁区判断）；另有「混合交错」与错题本（localStorage：`kurikaeshi-wrong`）。

## 重新构建

```bash
python3 build.py
```

- 发音按**文本哈希**缓存于 `audio/*.mp3`，改句自动重录、旧缓存自动清理；
- Nadeshiko 原声与缩略图缓存于 `nade_audio/`（已 gitignore，可重新下载）；
- 某条合成失败只跳过该处播放键，不影响整体构建（结尾列出失败清单）。

「断定の「に」統一引擎」见 `../ni-courseware/index.html`。
